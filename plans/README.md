## Recommended sequencing

1. **001** first — it's the most time-sensitive (a live refresh token is committed;
   rotation is an operator action flagged in the plan) and depends on nothing.
2. **002** next — it creates the test harness (`api/tests/conftest.py`, the
   `db_session` fixture) and the CI gate that **every other plan below relies on**.
   Nothing except 001 should run before it.
3. **003, 004, 005** — independent security fixes; any order once 002 is done.
4. **006 then 007** — 006 writes the characterization tests that 007's refactor is
   verified against. Do NOT run 007 before 006.
5. **008, 009, 010** — independent quality fixes; any order once 002 is done.
6. **011, 012, 013** *(current batch — financial integrity)* — independent of each
   other; any order. 011 first is recommended: it carries the migration (0042) and
   the highest-severity hole (duplicate rows from overlapping Teller syncs). 012 and
   013 are S-effort and can run in parallel worktrees with 011.

All of 011/012/013 edit `budget/service.py` in **non-overlapping functions**
(`bulk_import_transactions` / `create_transaction` / `_maybe_check_thresholds`),
but if you run them in parallel worktrees, rebase carefully — that file is large
and changes often. 011 is the only one touching `models.py` and `migrations/`.

## Findings considered and rejected

Verified by-design during the audit — do not re-flag:

- CORS uses an explicit origin allowlist + a safe `tauri://` regex (browsers never send
  `Origin: tauri://`), not a wildcard. (`main.py:452`)
- Dev impersonation is triple-gated: env check + `_ADMIN_ROLES` + same-household target
  verification. (`households/router.py`) — the only real issue was the fail-open
  `environment` default, addressed by plan 004.
- Refresh cookie sets `HttpOnly` + `SameSite=Lax` + `Secure` (outside dev). (`auth/router.py:58`)
- JWT decode pins a single algorithm (no alg-confusion); `jwt_secret_key` is required with
  no hardcoded fallback. (`auth/tokens.py`) — library staleness is tracked separately (#17).
- Teller mTLS: decoded key written to a `mkdtemp` (0700) dir, key file `chmod 0600`; base64
  failures logged without echoing secret material. (`teller_client.py:70`)
- First-run setup endpoint gated on `user_count == 0`. (`setup/router.py:74`)
- Auth datetime comparisons correctly use `_as_aware()`. (`auth/service.py`)
- Frontend dependencies are current (Next 16.2.4, React 19.2.4, TanStack Query 5.x) — no
  major-version lag worth acting on.
- `notes/service.py:148` / `templates/service.py:286` "unscoped reads" are read-backs off
  an already-household-scoped parent — low risk; folded into the boilerplate-duplication
  follow-up rather than treated as an IDOR.
